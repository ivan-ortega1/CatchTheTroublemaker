# Catch the Troublemaker / Catch l'entremaliat

A hyper-casual **multiplayer** game for 2–6 players on different machines. Two families share one randomly generated map: parents chase their own child, troublemakers collect coins and try to escape.

Two clients are available:

- **Unity Universal 2D client** — the project in this folder (`Assets/CatchTheTroublemaker`).
  It supports an authoritative Node backend **and a hostless P2P mode** with two
  session kinds: **Solo** (you pick a character and play with five bots, no network
  needed) and **Multiplayer** (2–6 players on the same LAN sharing a 5-letter code,
  no server, no host, no winner endpoint; empty seats are bots).
- **Browser client** — a dependency-free HTML5 fallback in `public/` (server mode only).

The server has **no npm dependencies** and no build step. See [docs/P2P.md](docs/P2P.md)
for peer-to-peer play.

---

## Quick start

```bash
node server/index.js
```

Requires Node.js ≥ 18 (tested on Node 24). Optional: `PORT=4000 node server/index.js`. For a quick demo match, `GAME_DURATION_MS=15000 node server/index.js`.

### Play in Unity

1. Open this folder in Unity 6000.6.9f1 (the Universal 2D template).
2. Open `Assets/Scenes/SampleScene.unity` and press **Play**. The scene already contains a **`GameManager`** object with `Network`, `UI`, `World` and `Input` children, an orthographic follow camera and an `EventSystem` — it is a conventional Unity scene, not a runtime bootstrap. (Use **Tools > Catch the Troublemaker > Setup Scene** to recreate that wiring.)
3. The home screen has a **Server URL** field (default `http://localhost:3000`) and a **TEST** button. `localhost` only works when the server runs on that same device; use the host's LAN IP (e.g. `http://192.168.1.20:3000`) on the same Wi-Fi. On **mobile data or another network**, publish port 3000 through a tunnel/cloud host and use that public URL instead — a LAN IP cannot be reached from mobile data.
4. Other machines on the same network find the server automatically (UDP LAN discovery) — the Home screen also has a **FIND LAN** button. Create a room or join with the 5-letter code, pick a role, and let the host start. The server prints the shareable LAN URL when it starts. See [docs/NETWORKING.md](docs/NETWORKING.md) for same-Wi-Fi, mobile-data and public tunnel setup.

The map and coins are generated procedurally; the imported artwork is the four family
portrait sets. Once the host picks two families, every character icon uses those
sprites: the `fatherA`/`motherA`/`troublemakerA` roles wear family A's father, mother
and troublemaker PNGs, and the `fatherB`/`motherB`/`troublemakerB` roles wear family B's.
This applies to the Unity menu legend, lobby role cards, HUD strip, score tags and
world actors (the local player still gets a thin white frame), and to the browser
lobby, HUD and canvas. Coins remain bright **yellow circles**; role colours stay as
the fallback when a PNG is unavailable and for accessibility cues.

**Family selector (all modes, both clients).** Before starting, the room creator/master
— or the Solo player — clicks **two different families** from `Assets/Sprites/Characters/Troublemakers`.
The cards are labelled **The Andersons** (`ClassicCaillou`), **The Other Andersons**
(`EmilyAnderson`), **The Johnsons** (`JonathanJohnson`) and **The Bills** (`LittleBill`);
the folder ids stay unchanged as the network keys. Each card shows the
troublemaker, father and mother sprites together and gets an **A** or **B** badge.
Click a selected card to remove it; a third card stays locked until one is removed.
These are display-only names: the internal family slots `A`/`B`, role colours and the
"only catch your own child" rule are unchanged. Two families are required before START
is enabled. In Unity the sprite catalog is generated by **Tools > Catch the Troublemaker >
Rebuild Character Catalog** (`Assets/Resources/CTTCharacterCatalog.asset`); the same tool
copies the PNGs to `Assets/Resources/CTTCharacters/<family>/` so the cards can load the
real sprites by path at runtime (the browser reads the original folders through
`/api/config`).

### Play peer-to-peer (no server)

Press **MODE: ONLINE** on the Home screen until it reads **MODE: P2P**, then use the
new **P2P: SOLO / P2P: MULTI** button:

- **Solo:** the button changes to **PLAY SOLO** and the join field disappears. Press
  it, pick the two families and your character in the lobby, then press **START**;
  the other five players are bots. No server, code or LAN connection is required.
- **Multiplayer:** one player presses **CREATE P2P ROOM** and shares the 5-letter
  code; the others join with that code. **START is blocked until at least 2 real
  players are connected and the master has picked two different families**; empty
  roles are bots. Peers on the same LAN discover
  each other automatically, agree on a seed and player list without a host, and run
  the same deterministic simulation in lockstep. Every peer computes the same winner
  locally — the HTTP result endpoint is not used.

Full details: [docs/P2P.md](docs/P2P.md).

### Play in a browser

Open `http://localhost:3000` (or `http://<server-ip>:3000`).

1. **Create a room.** The creator is the *host* (game master).
2. **Share the 5-letter code.** Each player opens the URL and joins with that code.
3. **Host picks two different families** on the family cards (two are preselected by default).
4. **Pick a role** in the waiting room (if you don't, one is assigned at kickoff). Free roles are played by **bots**, so 2 humans are enough.
5. **Host presses Start.** The server generates a new random map and begins the match.

## Rules

| Team | Win condition |
| --- | --- |
| **Troublemakers** | Any troublemaker reaches **50 coins**. |
| **Parents** | Both troublemakers are grounded (3 catches each) **or** the 6-minute timer expires. |

**The key asymmetry:** father A and mother A can catch **only** troublemaker A. Father B and mother B can catch only troublemaker B. A wrong-family tag does nothing — this is enforced on the server, not in the client.

When a child is caught they lose **all** their coins, are sent home for 3 seconds and cannot be caught again for 1.5 seconds. Parents may also **confiscate** coins by walking over them (900 ms cooldown per parent).

### How the difficulty is balanced

The "only your own parents can catch you" rule heavily favours the kids, so the following counters were added:

| Lever | Troublemakers | Parents | Why |
| --- | --- | --- | --- |
| Cruising speed | 6.3 tiles/s | 5.0 tiles/s | Kids can outrun a parent in a straight line. |
| Sprint | ×1.6, 1.4 s, 7 s cooldown | ×1.55, 1.4 s, 7 s cooldown | Parents get a *comparable* burst to close a gap, not an instant catch. |
| Lives | 3 each | — | One mistake is not the end of the match. |
| Coin penalty | Drop every coin when caught | Confiscate with cooldown | Parents can slow a kid without deleting the whole map. |
| Start | 5 s grace | — | Kids get a head start to build a lead. |
| Information | Everyone sees everyone | Everyone sees everyone | Keeps the rules legible; asymmetry comes from speed/roles instead of fog. |
| Bots | Fill empty seats | Fill empty seats | A match is never stuck waiting for a sixth player. |
| Opponent corner | Start far from own parents | Start far from own child | No instant spawn-camping. |

All values live in [`server/config.js`](server/config.js) so they can be tuned in one place. The reasoning and the iterations are documented in [`docs/AI_PROCESS.md`](docs/AI_PROCESS.md).

## Architecture

```
 Unity player ─┐                ┌── HTTP REST ── create / join / role / start / input / result
 Browser player┼── async ──────▶│  Node.js server (server/index.js)
 Unity player ─┘                │   • rooms & host control
                               │   • authoritative 20 Hz simulation loop
                               │   • SSE broadcaster (15 Hz snapshots)
                               └──▶ Match engine (server/engine.js)
                                      • seeded random map + BFS pathfinding (bots)
                                      • collision, coins, catch rule, win detection
                                      • pure module → unit-testable
```

- **Unity client structure:** `GameManager` owns the Home → Lobby → Playing → Result state machine. `NetworkManager` handles REST/SSE/polling, `UIManager` the uGUI overlay, `BoardRenderer` the **world-space 2D** sprites and follow camera, and `PlayerController` the Input System intent. Menu, lobby and game screens all use the selected family portraits; only intent is sent, positions never are.
- **Client → server:** small `POST /api/rooms/:code/input` messages carrying only `{dx, dy, sprint}`.
- **Server → client:** Server-Sent Events stream `hello`, `lobby`, `start`, `state` and `result`. Browsers use `EventSource`; Unity parses the same stream with a custom `DownloadHandlerScript`. Both also poll `/state` as a fallback.
- **Authority:** neither client decides coins, catches or the winner. Both only draw snapshots.
- **Mixed matches:** a Unity player can play against a browser player — they are just HTTP clients of the same room.

### Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/health` | Server status |
| `GET` | `/api/config` | Balance constants, role metadata and family cards with sprite URLs |
| `POST` | `/api/rooms` | Create room → `{ code, playerId }` |
| `POST` | `/api/rooms/:code/join` | Join (reuses `playerId` on reconnect) |
| `GET` | `/api/rooms/:code` | Lobby state |
| `POST` | `/api/rooms/:code/role` | Choose/swap role |
| `POST` | `/api/rooms/:code/families` | Host selects 0–2 distinct families (2 required to start) |
| `POST` | `/api/rooms/:code/start` | Host starts the match |
| `POST` | `/api/rooms/:code/input` | Player intent |
| `GET` | `/api/rooms/:code/events` | **SSE** stream of async updates |
| `GET` | `/api/rooms/:code/state` | Full snapshot (polling fallback) |
| `GET` | `/api/rooms/:code/result` | **Required endpoint: who won** |
| `POST` | `/api/rooms/:code/restart` | Host starts a rematch with a new seed |

```json
    "stats": { "catches": 6, "coinsCollected": 71, "confiscated": 12 }
  }
}
```

## Requirements checklist

| Requirement | Implementation |
| --- | --- |
| More than one player, each on their own machine | Unity and browser clients around one Node server |
| Lobby / master | Waiting room + host-only start/restart |
| Random board with spawn points | Seeded map generation, four corner spawns, BFS connectivity |
| Shared goal | 50 coins, 132 on the map with respawn |
| Asynchronous communication | Server-Sent Events + input POSTs, polling fallback |
| Endpoint returning the winner | `GET /api/rooms/:code/result` |
| Aesthetics / usability / accessibility | Procedural uGUI + canvas UI, CA/EN, keyboard + touch, ARIA live toasts (browser), high contrast, text sizing (browser), selected-family character sprites in both clients (colour/shape fallbacks), reduced motion (browser) |
| Developed with AI agents and documented | This repository + `docs/AI_PROCESS.md` + `docs/PRESENTATION.md` |
| Git | Repository initialised; commits at each milestone |

The original Universal 2D template structure (`Assets/Scenes`, `Settings`, `Packages`) is preserved; the game is added under `Assets/CatchTheTroublemaker/` alongside `public/` and `server/`.
